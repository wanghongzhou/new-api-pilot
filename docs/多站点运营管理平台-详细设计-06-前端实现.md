# 多站点运营管理平台 — 详细设计 06：前端实现

> 上级文档：[多站点运营管理平台-概要设计.md](./多站点运营管理平台-概要设计.md)  
> 详细设计索引：[多站点运营管理平台-详细设计.md](./多站点运营管理平台-详细设计.md)

本文档描述平台自身的独立前端工程。`web/default` 仅作为视觉、组件组合和工程模式参考；下文 `web/` 路径均指平台工程目录，不修改当前 new-api 的 `web/default`。

用户可见的聚合视图命名统一按语义区分：分类聚合使用“分析”，数量或占比构成使用“分布”，逐站原始记录使用“站点明细”，采集覆盖状态直接使用“完整性”。界面标题、Tab、图表、表格、空状态和无障碍名称不得使用含义偏技术实现的“拆分”；`breakdown` 仅保留为内部 API/代码术语。

全局查询参数遵循与官方 new-api 一致的非空传递规则：浏览器地址栏和 API 查询串均不得序列化空字符串、空数组、仅含空项的数组、`null` 或 `undefined`，不得生成无值键或多余的 `?`；数值 `0`、布尔值 `false`、有效 ID、时间范围、分页、排序和其他具有明确查询语义的值必须保留。该约束由共享路由序列化器和共享 Axios 客户端统一兜底，各 Feature 仍应只构造自身契约允许的参数；刷新、深链、浏览器历史、请求去重键与实际发出的 URL 必须使用同一份清理后的查询参数。

所有分页响应（包括共享 `PageData` 与模型目录、模型定价、分组配置、用户库存、渠道库存、订阅计划等自定义 Page DTO）的 `total` 均按后端 bigint 十进制字符串契约保留，并使用 `BigInt` 比较及千分位展示；是否存在下一页用 `BigInt(page) * BigInt(page_size) < BigInt(total)` 判断。只有当用 BigInt 算出的总页数不超过 JavaScript 安全整数上限时，共享分页才可转换该页数并保留页码与末页跳转；超过上限或调用方明确声明末页未知时，自动降级为首页、上一页、当前页和下一页的顺序导航。禁止先把 total 转为 JavaScript number 或用 `Math.ceil(total/page_size)` 规划页数。筛选项需要聚合多页时也必须逐页读取，达到服务端声明 total、遇到空页或达到明确安全页数上限即停止；不得根据可能超过安全整数的 total 一次性生成页码或并发请求数组。深链落到数据删除后的空页时，若 BigInt 计算出的末页仍在 JavaScript 安全整数范围内，必须一次 `replace` 到精确末页；只有末页本身超过安全整数、无法安全写入现有 number 型路由页码时，才逐页回退，避免常规 `page=999999` 深链制造大量串行请求。

根入口 `/` 与目录入口 `/settings` 属于规范化重定向，必须使用 history replace，浏览器返回不能再次落入同一跳板。未知路由提供“返回上一页”和“返回工作台”两条恢复路径；无可用上一页时仍可稳定返回工作台。实体详情的首次 404/403 与可重试网络或 5xx 必须区分：不存在和权限不足不得显示无意义重试，网络/5xx 才提供重试；已有缓存后的刷新失败继续展示缓存和陈旧警告。以上错误、空、加载与陈旧状态均须有可访问语义，不能把 404、403、网络失败折叠为同一文案。

~~~text
  ├─ 运营概览
  └─ 告警中心
业务管理
  ├─ 站点管理
  ├─ 客户管理
  └─ 账户管理
任务与日志
  ├─ 使用日志
  ├─ 任务日志
  ├─ 系统任务
  └─ 导出中心
运营分析
  ├─ 财务运营
  ├─ 全局统计
  ├─ 本地排行
  └─ 性能趋势
资源中心
  ├─ 用户库存
  ├─ 渠道库存
  ├─ 模型审计
  ├─ 定价与分组
  └─ 订阅计划
平台管理
  ├─ 平台用户
  └─ 系统配置
~~~

主导航按使用频率和用户工作心智固定排序，不按后端模块或交付批次排序。告警中心显示当前未解决告警数量徽标；徽标复用告警汇总查询、定时刷新。首次查询失败且没有旧数据时显示“告警数未知”的非数字状态，不能隐藏为无告警或以 `0` 冒充无告警；已有旧数据时后台刷新失败继续显示旧数量，同时标记该数量可能已过期。每个导航入口使用可区分的语义图标，不复用通用服务器或导出图标代表无关功能。分类、名称与排序调整不改变现有路由和 API 契约。

所有主导航目标的文件路由匹配身份必须与公开无尾斜杠 URL 完全一致。公开路由为 `/name` 时不得使用会生成 `/name/` 匹配身份的目录 `index.tsx`；Dashboard、实体管理、任务日志、运营分析、资源中心和平台管理中的每个顶层目标都必须使用无尾斜杠文件路由。主导航统一渲染保留真实 `href` 的原生文档级链接，不得依赖客户端 Link、局部页面白名单或 reload 标记；任何页面的搜索参数规范化、查询保留和异步状态都不得吞掉离开当前页的导航。设置页未保存变更仍可在导航事件阶段取消跳转。导航回归必须从全部主导航顶层页面执行真实 `link.click()`，验证能离开当前页面并到达另一目标路由，不得仅用 `page.goto()` 或只核对导航配置数组替代。

### 23.1 权限表现

- admin 展示全部按钮；
- viewer 隐藏所有写操作；
- viewer 保留查看、筛选、下钻和导出；
- 后端权限校验为最终依据。

### 23.2 数据状态表现

- complete：正常展示；
- pending/backfilling：显示进度和部分数据提示；
- missing：显示缺失，不补 0；
- unavailable：显示上游不可恢复；
- paused：显示暂停原因；
- 所有页面展示数据更新时间。

### 23.3 国际化

前端使用 i18next 和 react-i18next，产品语言固定为简体中文 `zh-CN`。所有用户可见文案使用翻译键，不在组件中硬编码；本期不提供语言检测、语言切换或其他 locale 资源。

### 23.4 登录与强制改密页面

- /sign-in：用户名、密码、登录按钮；
- bootstrap admin 使用环境变量或一次性密码首次登录后跳转 /change-password；
- must_change_password=true 时不能进入其他路由；
- 已登录用户可从 Header 进入 /change-password 自助修改密码；
- `/change-password` 运行在已登录应用 Header 下时不得再次渲染登录页品牌或指向 `/sign-in` 的品牌链接；页面只保留一个应用身份与导航层级，避免无效跳转和重复品牌占用移动端首屏；
- 修改完成后进入 Dashboard；
- 用户名不存在、密码错误和禁用用户提交错误密码只提示用户名或密码错误；凭据正确但账户禁用时明确提示账户已禁用。
- 原密码错误显示在修改密码表单的当前密码字段。
- 登录密码只校验非空；创建用户、重置密码和修改密码校验至少 8 个 Unicode 字符，并用 TextEncoder 校验 UTF-8 不超过 72 字节。

### 23.5 平台用户页面

路由：/settings/users

- 用户名、显示名、角色、状态、最近登录时间；
- admin 可新增 admin/viewer；
- admin 可编辑角色、启用、禁用和重置密码；
- 重置密码后 must_change_password=true；
- 最后一个可用 admin 的禁用按钮置灰；
- viewer 可以查看用户列表，但没有写操作。
- 状态、最近登录时间和创建时间列支持服务端升序/降序排序，排序字段与方向写入 URL；默认 created_at desc。
- 列表已有数据后的刷新失败必须保留旧数据并明确标记为可能过期，提供重试入口；在列表过期或管理员保护计数未知时，禁用编辑角色、重置密码、启用和禁用等写操作，避免基于旧状态执行管理动作。服务端返回非空总数且当前页超过最后一页时，前端使用 replace 导航校正到最后有效页；显示名在桌面与移动端均允许完整读取，不得只提供无替代入口的截断文本。
- 创建、编辑和重置密码流程在请求进行中不得通过遮罩、Esc 或取消按钮关闭；重置密码已输入但未提交时，关闭必须确认放弃修改。

### 23.6 系统配置页面

路由：/settings/system

- 六个固定设置分组使用页内分类标签切换，默认显示采集策略；分类栏紧贴页面标题区域并固定在内容滚动区顶部，固定区域使用不透明背景，向下查看长分组时不得透出后方文字且仍可直接切换。当前分类写入 `section` 查询参数，支持刷新和深链恢复；恢复深链、浏览器前进后退或校验错误切换分类后，激活标签必须完整滚入窄屏水平分类容器的可视区域，不得只更新内容而把当前分类留在容器外。每次只渲染当前分类，切换分类不得丢失尚未保存的表单值，保存仍按一次批量 PUT 提交所有分类中的实际改动；窄屏分类栏允许横向滚动，不得造成页面级横向溢出或带动设置内容横向偏移；设置项在中小屏使用上下布局，只有宽屏才使用说明与输入控件左右布局，避免说明列被固定宽度输入控件过度挤压；
- 设置首次加载失败且没有成功缓存时显示阻断错误态；已有成功缓存后的后台刷新失败不得用整页错误覆盖缓存，应显示可重试的陈旧数据警告并继续呈现最后一次成功响应。陈旧期间管理员与 viewer 一样只读，隐藏保存、撤销、敏感配置操作和测试发送入口，禁止产生 PUT/测试请求；刷新恢复成功后才重新开放管理员写操作，避免用旧基线覆盖其他会话刚写入的设置；
- 分类标签必须标记各分类是否包含未保存修改。保存前的客户端校验或服务端字段错误若属于非当前分类，页面自动切换到第一个错误所在分类、在内容顶部显示可见且通过 `aria-live` 宣告的错误摘要，并聚焦首个错误控件；不得让保存静默失败。全局撤销所有未保存修改必须二次确认。
- 表单存在未保存修改时，站内路由离开和浏览器刷新/关闭均必须提醒；保存成功或确认撤销后解除提醒。viewer 的只读值必须通过 `aria-labelledby`/`aria-describedby` 或等价语义与设置名称、说明建立程序化关联。
- 站点状态检查、实时统计和资源采集周期以 1～60 分钟显示和编辑，提交时转换为后端整分钟秒数，保存后无需重启；小时采集延迟同样可编辑；
- 并发上限；
- 手动补采单次最大天数；
- 分钟资源、上游日志、性能历史、采集任务和系统任务终态的留存天数；
- 导出文件有效期、单用户/全局活跃上限、最大文件和磁盘余量；两个字节设置在界面以整数 MB 显示和编辑，并以 `1 MB = 1024 × 1024 bytes` 使用 BigInt 精确换算为后端十进制字节字符串；
- PUBLIC_ORIGIN 只读展示为“平台公开地址”，并以运营文案说明其用于校验浏览器写操作是否来自本平台以及生成钉钉告警详情链接；同时提供钉钉机器人地址、签名密钥和右对齐的测试发送按钮；
- 汇率兜底值；
- 快速任务历史有效期/条数，以及上游主机后缀、IP 网段、四级超时、请求频率和同一上游地址共享并发；有效期在界面以小时显示和编辑，提交时乘以 3600 转换为后端 `fast_task.history_retention_seconds` 整数秒。说明必须明确：条数在每次写入时立即截断旧记录，有效期在每次写入时刷新，并在对应站点和任务类型持续无新记录达到有效期后清理整组短期历史；
- 上游主机后缀与 CIDR 使用多行文本框编辑，允许换行或逗号输入，展示时一项一行，提交前去空白、去重并规范化为逗号分隔；两项同时为空的说明必须明确为“仅允许安全公网”，不得描述为关闭限制；
- 敏感值只显示掩码，不回显明文；
- 敏感项提供“替换”“显式清除”两个独立动作；清除必须二次确认并发送 clear=true，空输入表示不修改；
- decrypt_error 时显示稳定错误码和重新配置动作，不展示密文或后端解密详情；测试消息只使用已保存配置，未启用/未配置/解密失败时按钮禁用并说明原因；
- 页面不展示 H+15 发布资格；采集延迟和并发仅作为普通可编辑设置显示，由字段范围校验约束；
- 仅 admin 可修改，viewer 只读。
- 页面通过 Viewer 可读的 `GET /api/settings` 一次取得六个固定分组；`system.public_origin` 只读且不进入 PUT；普通整数始终发送 JSON number，两个字节阈值和两个 decimal 始终按十进制字符串处理，不经过 JavaScript number，decimal 输入只提交 ASCII 固定点形式；
- 保存只发送实际编辑项，不携带 updated_at/version。后端按全量行锁原子 last-write-wins；成功后以响应中的 updated_at 替换本地快照，失败时整批保留原表单值；
- Webhook/secret 空输入表示保持，替换和 clear=true 是两个显式动作；enabled=true 时两项必须均已配置且可解密。decrypt_error 项只能替换或在停用同批次中显式清除。

## 35. 前端技术基线和目录

### 35.1 技术基线

- React 19 + TypeScript；
- Rsbuild；
- 本地开发由 `docker-compose.dev.yml` 中常驻 Bun/Rsbuild 服务提供 5173 端口和源码 bind mount；开发迭代中的普通 TS/TSX/CSS 修改依靠 HMR 生效，不重新构建 Go 镜像，`/api` 在容器网络内代理到 `api:3000`。HMR 只用于迭代反馈，不能替代交付前的干净启动验证：只要本次包含前端变更，交付前必须重启 `web` 服务并重新检查健康状态；修改 locale JSON、i18next 初始化或翻译资源注册后还必须硬刷新受影响页面，禁止把原始 i18n key 当作已生效；
- TanStack Router 文件路由；
- TanStack Query；
- TanStack Table + TanStack Virtual；
- Base UI 对应的 shadcn 组件，风格 base-nova；
- Tailwind CSS v4；
- Public Sans；
- Hugeicons 作为本项目新增图标来源；
- @visactor/react-vchart 作为统计图表；
- i18next + react-i18next；
- react-hook-form + zod；
- Sonner 消息；
- Motion 页面与侧栏过渡，并遵守 `prefers-reduced-motion`；
- Decimal 高精度金额计算。

本平台的前端工程基线以官方 `new-api` 仓库当前版本的 `web/default` 为唯一上游，React、TypeScript/tsgo、Rsbuild、TanStack、Base UI、shadcn base-nova、Tailwind CSS、oxlint、oxfmt、Bun/Node 等共享技术栈及共享依赖版本必须与上游保持一致。升级时先核对上游 `web/package.json` catalog、`web/default/package.json`、Bun lockfile以及 Rsbuild、TypeScript、oxlint、oxfmt、shadcn 配置，再在本平台完成对应升级和全量前端验证；不得自行引入另一套构建器、路由器、状态管理、组件基础设施、CSS 方案、图标体系或格式化/检查工具。

“技术栈和工程风格对齐”不表示复制 new-api 业务。平台继续使用自身 API 契约、路由、权限、功能目录、文案和领域模型，不导入或依赖 new-api 的业务包。依赖清单按实际使用能力取上游的必要子集：与上游同名的共享依赖必须使用相同版本；仅服务于 new-api 自身业务且平台未引用的依赖不得为追求清单表面一致而安装；平台因独立业务、Decimal 精度、Bun 单元测试、Playwright 验收、路由生成或契约检查所需的附加依赖可以保留。Rsbuild 代理目标、HTML 品牌元数据、TypeScript include/types、lint 的业务导出白名单等配置允许作同类薄适配，但编译目标、严格性、代码分割、生产优化、Tailwind 插件、TanStack Router 插件、格式规则和通用 lint 规则必须保持上游语义一致。

## 36. 路由、URL 状态和权限

### 36.1 根认证守卫

_authenticated/route.tsx 参考 new-api web/default 现有模式：

1. 本地 auth store 无用户时跳转 /sign-in?redirect=当前地址；
2. 每次浏览器会话首次进入时调用 GET /api/user/self；
3. 401 清空 auth store 并跳登录；
4. 网络错误或 5xx 不误判退出，显示全局错误并允许重试；
5. must_change_password=true 且目标不是 /change-password 时重定向；
6. must_change_password=false 时允许访问 /change-password；普通认证页面按各自权限继续访问。

登录成功保存最小用户信息和 uid。退出只有在服务端注销成功后才清除 auth store、uid、Query Cache 并跳转登录页；网络错误或 5xx 时保留当前登录状态，明确提示“退出失败”并允许重试，不能让用户误以为服务端会话已经撤销。

uid、siteId、customerId、accountId、alertId、runId、exportId 等 BIGINT ID 在 TypeScript 中统一为 string，不允许 `Number(id)`；Unix 秒时间戳保持 number。

### 37.3 Mutation 失效

| Mutation | 成功后失效 |
|---|---|
| 新建/编辑/停用/恢复站点 | siteKeys.all、dashboardKeys.health、dashboardKeys.summary |
| 授权/探活/刷新站点 | 对应 site detail/list/status/runs |
| 重新检查站点能力 | 对应 site detail/list/runs；通过后轮询 backfill |
| 新建/编辑/停用客户 | customerKeys.all、accountKeys.lists、相关 statisticsKeys |
| 添加/归档/恢复账户 | accountKeys.all、customer detail/list、相关 statisticsKeys |

| 修改系统配置 | settingKeys.all；受影响的轮询配置重新读取 |
| 修改平台用户 | userKeys.all |
| 修改自己密码 | auth self；随后清除 PASSWORD_CHANGE_REQUIRED 状态 |

Mutation 成功显示 Sonner success；失败由共享 Axios/QueryClient 处理。删除和状态切换不做乐观更新，避免后端约束失败导致 UI 回滚复杂。站点 authorize/recheck-capabilities 使用共享 Axios 的 30 秒有界超时；后端能力检查必须使用有界探测策略在该窗口内返回成功或结构化业务错误，不得依靠放宽前端超时掩盖串行上游请求。UPSTREAM_LOGIN_REJECTED 显示“上游登录失败，请检查用户名或密码”，SITE_INCOMPATIBLE 仅用于 root 身份/首用户证明或 API 契约不兼容。

- Dashboard 四个接口在同一 render 中并行 useQuery；
- 站点详情基础信息、今日统计、实例和 collection run 并行；

- 模型和通道筛选使用 `/api/statistics/options/*` 服务端搜索，不一次性加载全部 distinct 值；
- 只有 account 远端用户搜索依赖先选择 site_id，使用 enabled 控制；

- route loader 仅预取首屏关键数据，不串行预取所有 Tab。

### 38.2 状态组件

统一组件：

- DataStatusBadge：complete/partial/pending/missing/unavailable/paused/backfilling；
- SiteStatusBadges：在线、授权、统计、资源健康四组 Badge；
- DataFreshness：显示“业务数据截至”“当前状态更新于”“已过期”；
- CompletenessAlert：完整率、unit_type 对应的 complete/expected 单元数、最后时间桶站点数、缺失站点、缺失范围和跳转；
- BackfillProgress：进度条、完成范围、失败数、最近错误；
- QuotaAmount：原始 quota + USD/CNY，可切换显示，内部 Decimal；
- MetricValue：bigint 字符串格式化，保留 title 精确原值，并遵循统一空值展示契约；
- Empty、Skeleton、Alert、Sonner 使用共享 shadcn 组件。

标量展示遵循统一空值契约：真实数值 `0` 必须显示为 `0`，不得被空值判断吞掉；数值类型在数据缺失、无法计算或当前没有可展示结果时统一显示 `0`，字符串、时间及其他文本标量在 `null`、`undefined` 或空字符串时统一显示半角短横线 `-`。后端和前端状态机继续保留 `unavailable` 等内部状态，以便状态徽标、重试入口和完整性判断保持准确，但用户可见文案必须改为“采集失败”“暂未获取”“无法计算”等具体原因，禁止使用笼统的可用性否定词；状态存在时也不改变数值和文本的统一占位规则。`MetricValue`、`formatNumericDisplayValue`、`formatMetricDisplayValue` 和 `formatDecimalDisplayValue` 的默认空值均为 `0`，`formatDisplayValue` 的默认空值为 `-`。共享展示代码使用这些入口，禁止以 `value || fallback` 处理可能为 `0` 的值。

### 38.5 账户表格和卡片

账户管理与站点、客户管理使用同一套固定视口列表布局：筛选栏右侧提供卡片/表格切换，默认卡片视图，视图偏好写入 `accounts:view-mode`。URL 中显式 `view=card|table` 时优先使用 URL；两种视图共享筛选、排序、页码和每页数量。卡片区与表格区占满筛选栏下方的剩余高度并在内部滚动，分页统一固定在公共页脚。初始加载、加载失败、空结果和后台刷新状态在两种视图中保持一致；移动端默认卡片视图，主动选择表格时仍不得产生页面级水平溢出。

1. 基础信息：名称、规范化 base_url、备注；

### 38.6 告警表格

列：level、status、rule、site、target、current/threshold、first_fired_at、last_fired_at、resolved_at。默认 firing first、level desc、last_fired_at desc。Critical 使用 destructive Badge，Warning 使用 warning 语义变体，不靠颜色单独表达，必须同时显示图标和文本。

点击行打开只读 Sheet，展示事件时间线和钉钉投递结果；不显示确认、负责人、备注和关闭按钮。

`/alerts` 使用“事件 / 规则”Tabs。事件 Tab 顶部通过 `/api/alerts/summary` 展示 firing、Critical、Warning、今日恢复；统计更新时间位于统计概览外，并与“事件 / 规则”Tabs 共用同一行，Tabs 左对齐、更新时间右对齐。更新时间只属于事件概览，切换到规则 Tab 后必须隐藏。四项统计与模型审计顶部概览使用同一种独立卡片网格：每项拥有独立圆角卡片、语义图标区、标签和高强调大数字，不再用一个胶囊容器和内部竖线包裹全部指标；图标只用于增强识别，文字和数字始终保留。事件表格第一列为规则，列表默认使用后端复合优先级；只允许规则、状态、级别、站点、首次触发、最近触发和恢复时间排序，其中级别、站点、最近触发和恢复时间必须提供明确的升序、降序入口，表头字段必须与 API sort_by 一致。alertId 深链打开详情。

事件筛选数量少，状态、级别、目标类型、站点和时间范围全部常显，不提供展开/收起。状态、级别和目标类型复用规则页的 FacetedFilter 单选组件并即时生效；站点下拉空值文案固定为“全部站点”。时间范围使用参考 new-api 的紧凑弹出式起止时间控件，触发按钮显示当前范围，弹层提供北京时间起止输入和今日/近 7 天/近 30 天快捷范围，确认后一次写入 URL。

collection 告警不直接展示 canonical target_key。collection_missing/validation_failed 显示“统计窗口”及格式化后的北京时间小时，backfill_failed 显示“回填任务 #run_id”；底层 `site_id/hour_ts` 或 `site_id/run_id` 仍用于事件去重和唯一定位。事件当前值、阈值以及告警消息中的 value/threshold 展示均按指标语义格式化：CPU、内存、磁盘、响应时间与可用率最多保留 2 位小数并去除尾随 0；渠道余额保留有效原始精度但同样去除无意义尾随 0，规范零固定显示为 `0`，不得显示为 `0.0000000000`。API 与数据库 current_value 原精度不变。

规则 Tab 展示 rule_key、级别、metric、比较符、阈值、连续次数、global/site、继承状态和更新时间。admin 可编辑 enabled/threshold/for_times，可选择站点从全局规则创建覆盖，也可删除站点覆盖回落全局；viewer 全部只读。布尔/身份类规则的 threshold 与 compare_operator 只读，仅允许 enabled；成对阈值按比较符联动校验：`>=` 规则要求 Warning<Critical，`<=` 规则要求 Warning>Critical，`==` 规则要求两级相等。告警规则及告警事件中的阈值统一最多显示 2 位小数并去除无意义尾随 0，编辑框只接受最多 2 位小数，阈值范围提示遵循同一格式。事件 current_value 在 API 和数据库中保留指标原始精度，但告警事件列表、卡片和详情最多显示 2 位小数并去除无意义尾随 0；该展示规则不得影响货币、消耗、余额、额度或汇率等其他 decimal 数据。保存冲突显示字段错误，不在前端悄悄调整阈值。

### 38.8 采集记录表格

完整采集历史使用独立路由 `/sites/:siteId/collection-runs`，不得把数万条持久任务和 Redis 快速任务历史直接铺在站点详情长页面中。站点详情只展示最近 3 条持久任务的紧凑摘要、总任务数以及“查看全部采集记录”入口；摘要不提供分页、筛选或窗口 Sheet，也不加载快速任务历史。完整采集页以“采集记录 / 快速任务历史”两个 URL 驱动的 Tab 分隔持久任务与 Redis 短期历史，默认进入“采集记录”；不得在同一纵向页面同时加载和轮询两张长表。两个 Tab 分别保留自己的筛选和页码，任务窗口深链始终自动切回“采集记录”。每个 Tab 的标题和说明位于左侧，筛选区位于同一行右侧；每个筛选项使用可见文字标签在左、下拉框在右的紧凑布局，只有窄屏空间不足时才自然换行。完整采集页默认每页 10 条，每个 Tab 仅在列表下方显示一组总数与分页，移动端使用 cards；筛选、页码、任务窗口深链写入 URL，越界页自动修正到最后有效页。普通长页面由页面内容区负责纵向滚动，表格区域只负责宽表的横向滚动，不得用内部纵向滚动或 overscroll containment 阻断页面滚轮。

持久任务表列：任务 ID（`collection_run.id`）、task_type、trigger_type、range、status、fetched_rows、written_rows、retry_count、duration、error、created_at；移动卡片、站点详情最近任务摘要和任务详情 Sheet 同样明确显示该任务 ID。running/pending 每 5 秒刷新。错误列截断，点击打开 Sheet 查看完整安全错误和 request_id；不显示远端 Token。任务 ID 是告警 `backfill_failed.run_id` 与任务详情深链使用的稳定逻辑 ID，request_id 仅用于定位一次请求/执行尝试，二者不得混称。task_type 使用平台固定的 19 项目录，并按 fast、durable、hourly、usage、rebuild 分组；每项同时展示用途文案。目录如下：

- fast：`site_probe`、`realtime_stat`、`resource_snapshot`，用于站点探活、实时指标和资源快照；
- durable：`performance_sync`、`topup_sync`、`redemption_sync`、`upstream_task_sync`、`model_meta_sync`、`plan_sync`、`pricing_group_sync`、`system_task_sync`，用于各类持久化运营数据同步；
- hourly：`user_sync`、`channel_sync`、`log_sync`，按小时边界同步站点用户、渠道和日志；
- usage：`usage_hour`、`usage_backfill`、`usage_validation`，用于小时用量、历史补采和完整性校验；
- rebuild：`account_rebuild`、`customer_rebuild`，用于账户和客户统计重建。

快速任务历史只接受 fast 的三个 task_type；未知 task_type 阻止展示并显示契约错误，不以空列表掩盖服务端返回异常。

“快速任务历史”Tab 调用 `/api/fast-tasks`，仅在该 Tab 激活时加载和执行 5 秒轮询。admin 和 viewer 均可按 `site_probe/realtime_stat/resource_snapshot` 与 `running/success/failed` 筛选，使用 offset/limit 展示最近执行；列为任务 ID、task_type、status、started_at、finished_at、duration_ms、error。快速任务没有 MySQL `collection_run.id`，其既有唯一 `request_id` 即该次快速任务的任务 ID，桌面表格和移动卡片都以“任务 ID”标签完整显示，便于与日志/告警证据对应；不得另造无法关联的展示编号。该列表明确标注为 Redis 短期历史，不与持久 collection run 合并、不承诺跨 TTL 或重启长期保留；加载失败显示独立错误，切回“采集记录”后仍保留快速任务筛选与页码 URL 状态。

任务详情 Sheet 调用 `/api/collection-runs/:id/windows`，按 pending/running/success/failed/unavailable 执行状态筛选，分页展示 hour_ts、fact_status、attempt_count、next_retry_at、verified_at 和稳定错误码；每行是该 run 不可变归属的 collection_run_window，新 run 不覆盖旧行。“重试失败窗口”创建新 run，不能直接篡改旧 run。桌面端 Sheet 必须使用可容纳窗口表格的宽面板，移动端占满可用宽度；标题区固定在顶部，详情与表格区域在面板内纵向滚动，宽表只在表格容器内横向滚动。窗口列表只能显示一组总数与分页，不得在筛选区和表格底部重复渲染分页。完成范围由 run-window 列表/计数推导，超过一页时明确显示分页而不是假装已列全。失败 run/window 不得因历史错误参数多出诊断字段而显示为 `-`：后端按稳定 MessageRef 白名单裁剪后返回。`COLLECTION_EXECUTION_FAILED.failure_kind` 必须本地化为明确、可操作的脱敏原因；只有历史或未知错误缺少该分类时，才显示“采集任务执行失败，请提供下方请求 ID 查看服务日志”。前端不得渲染原始 code、错误文本、URL、凭据或诊断参数。

### 38.9 详细统计 Breakdown 列

P0-A 在共享 TypeScript DTO/API client 基础上新增 group/token/node 页面与统计二级导航。路由固定为 `/statistics/groups`、`/statistics/tokens`、`/statistics/nodes`，复用现有统计页的时间范围、小时/日/月/年粒度、指标、趋势/明细、完整性、逐桶 site_breakdown 金额换算和导出闭环。StatisticsQueryParams、ExportFilters、query key 稳定化必须保留 use_groups/token_keys/node_names；联合 breakdown 增加 Group/Token/Node 变体，token_id 保持 string。

三个页面的维度选项必须分别来自 options/groups、options/tokens、options/nodes，不得从当前分页结果猜测 distinct 选项。group 使用原始 use_group，空值显示“未知分组”；token 使用 site_id:token_id 作为 token_key，token_id 包括 0 在内始终保持十进制字符串，名称为空或 0 时显示明确未知/已删除状态；node 使用原始 node_name，空值显示“未知节点”。URL 保存站点和本维度多选筛选并支持刷新、复制、前进后退；375px 使用现有响应式筛选 Sheet/卡片布局，不横向溢出。complete 零、partial、missing、unavailable、paused 的展示和无障碍语义与六个既有统计页一致。

| 页面 | 主维度列 | 附加列 |
|---|---|---|
| global | 时间桶 | 完整站点/预期站点 |
| sites | site | 状态、汇率、完整率 |
| customers | customer | 账户数、站点数、site_breakdown |
| accounts | account | site、customer、remote_user_id |
| models | model_name | site |
| channels | channel_name/channel_id | site、remote_missing |

所有页面共同显示 request_count、quota、USD、CNY、token_used、active_users、data_status、as_of。账户 active_users 按 API 的派生值展示：`"1"` 表示范围内有事实，`"0"` 表示 expected 全部完整且无事实，`null` 才显示“—”并同时展示非 complete 的 data_status；前端不得自行固定为“—”或伪造 1。

### 38.10 Dashboard

Dashboard 使用固定视口工作区和内部纵向滚动，在桌面端采用 12 列驾驶舱布局。业务区块固定为“今日经营、实时吞吐、近 30 天趋势、今日快速排行、站点健康/完整性/告警”五个，不得增加第六业务区块；视觉顺序为“今日经营 → 趋势与实时状态 → 排行与健康明细”，不得继续把五个同权重区块纵向堆叠：

- 异常关注不是独立业务区块，归入“站点健康/完整性/告警”区块并在该区块内优先展示；它汇总 firing/critical/warning 告警、离线站点、授权过期站点、统计未就绪站点和昨日校验状态，异常数量提供带对应 `status/level` 或站点状态筛选的告警中心/站点管理下钻，不能只打开未筛选的全量列表；实时或资源过期站点 ID 直接进入对应站点详情；正常状态使用低强调语义，不以绿色大卡抢占首屏；
- 今日经营使用一组同层级主指标展示请求、quota、当前汇率金额、Token 和活跃账户，同时保留 `data_status/is_final/as_of/reason`，非完整数据不能显示为真实零值；
- 近 30 天趋势为桌面主分析区，实时 RPM/TPM、站点/客户/账户/实例规模以及实时与资源覆盖组成右侧运行态侧栏；两类覆盖均展示 complete/expected、`data_status/as_of/reason` 和过期站点；趋势区进入全局统计时必须冻结当前 30 天范围、粒度和所选指标；
- 今日排行支持站点/客户/模型/通道与请求/quota 切换，并与最近告警、异常站点、昨日完整性并列展示；首次进入只请求当前可见的客户排行，切换维度后按需请求并缓存该维度，禁止为了隐藏的 Tab 同时发起四个排行请求；排行项直接下钻到冻结为北京时间今日范围且带对应对象筛选的详细统计页；健康明细以站点权威 `online=online`、`auth=authorized`、`statistics=ready`、`health=ok` 作为正常组合，优先展示异常站点，全部正常时显示明确健康状态，不重复铺满全部正常站点卡片；
- 页头提供告警中心和全局统计快捷入口。summary、trend、当前可见 top 和 health 四个查询继续并行且失败隔离；已有旧数据时后台刷新失败保留旧数据并提示，包括旧数据为空数组的情况；单区块初始失败只影响该区块；
- 小于 1024px 时所有区域降为单列或双列自然流，指标和下钻按钮满足触摸目标，不产生页面级水平溢出。

### 38.11 站点列表与详情看板

站点列表概览三部分数据：站点身份与状态；实时实例/资源状态；与 new-api 数据看板一致的八项指标“请求、额度、Token、平均 RPM、平均 TPM、成功率、平均延迟、吞吐量”和完整率。桌面端默认使用分组列表，把每个站点整理为“站点与状态 / 资源 / 今日用量 / 性能 / 完整性与入口”五个稳定信息组；不得拆成十余个单值窄列，也不得因改为列表丢失卡片中的复制地址、统计详情、实例详情、站点详情和管理操作。资源组展示实例、CPU、内存、磁盘及资源采样时间；今日用量组固定第一行展示今日额度和今日 Token，第二行展示今日请求、平均 RPM、平均 TPM；前三个标签必须显式带“今日”，避免与生命周期累计值混淆；性能组展示成功率、平均延迟、吞吐量及性能采样时间；完整性组展示百分比进度。小于桌面表格断点时使用同字段纵向卡片，确保 375px 无页面横向溢出。前五项读取北京时间今日窗口的本地汇总；后三项读取最近一次成功采集的 24 小时性能 summary，严格复用 new-api `PerformanceHealthPanel`：成功率简单平均全部有限值，平均延迟和吞吐量简单平均大于 0 的有限值。success_rate 已是百分数，延迟按 new-api 规则显示 ms/s，吞吐量显示 `t/s`。缓存读取失败或没有有效模型时显示对应状态，数值按统一规则显示 `0`。完整率由后端按最新回填任务的冻结范围返回：全量回填使用完成窗口占比；缺失补采或失败窗口重试必须保留范围内此前已经完整的小时，只扣除本次仍未完成的窗口，不能因最新重试任务仅包含一个失败窗口而从 99% 以上跳成 0%。成功且因所选范围没有待补采窗口而以 `total_windows=0`、`completed_windows=0` 完成的回填属于完整的空操作，完整率必须为 100%，不得误报为 0%。未成功且尚未物化窗口的任务仍显示 0%。列表和卡片必须复用同一完整率格式化规则：仅真实完整率达到 100% 时显示 `100%`；任何小于 100% 的值最多显示两位小数且不得因四舍五入伪装成 `100%`，从而保证百分比与“部分完整”等状态标签语义一致。不展示实时 RPM/TPM。

站点“手动补采”对话框的开始和结束时间只接受北京时间整点。控件必须保留一小时步长，打开时默认显示最近一个已对齐整点向前一周的范围，并在前端 schema 中拒绝分钟或秒不为零的值、把错误显示在对应字段且阻止提交；不得把 `10:30` 静默截断为 `10:00` 后创建与用户选择不一致的任务。空值仍表示采用服务端默认边界。

用量速率的产品文案恢复为源站一致的“平均 RPM”和“平均 TPM”。站点列表固定使用滚动最近 24 小时，总请求数和总 Token 数分别除以 1440；其他统计范围除以请求起止时间的自然分钟数。缺失窗口通过 data_status、as_of 和完整率提示，不得从分母移除，否则会把平均值放大。Token 包含上游事实中的全部 token_used；界面不得把平均 TPM 与 `/api/log/stat` 的实时 TPM 或性能接口的生成吞吐量混称。

站点详情定位为单站运营概览，不再内嵌完整单站统计看板或实例列表；完整统计固定进入 `/sites/:siteId/stats`，实例详情固定进入 `/sites/:siteId/status`，避免与站点卡片已有的统计/实例入口以及独立页面重复。详情内容顺序固定为：状态与实时概览、性能健康、完整性与回填、站点配置与历史边界、最近采集摘要、相关页面导航。相关页面是离开详情页的导航，必须放在正文最下方；站点配置与历史边界属于当前站点上下文，应在导航之前展示。当前概览必须按纵向三行组织：第一行是 24 小时业务指标，第二行是 CPU/内存/磁盘资源指标，第三行是性能健康摘要；每行占满可用宽度，行内指标等高对齐。实例数、资源数据状态和采样时间作为资源行的辅助状态展示，不得改变三行主指标的布局。性能健康摘要不再使用不等高的指标表格，成功率、平均延迟、吞吐量固定为三个等宽横向胶囊；逐模型明细默认每页 10 条并提供分页，不能因模型数量增长而把所有行持续展开；分页只影响展示，不改变性能摘要口径。相关页面导航按“运营分析、资源与目录、日志与任务、基础设施”分组并在正文内自然换行；页头只保留管理操作菜单，不得放置十余个快捷按钮。375px 下正文必须自然纵向滚动，不得因页头换行占满可用高度或产生页面级横向溢出。

性能健康区块提供 24 小时、7 天（168 小时）、30 天（720 小时）切换，调用 `GET /api/sites/:id/performance`。它是单站实时代理例外，不与 `/api/sites/:id/stats` 混为用量统计；显示 models、sampled_at 和 data_status。区块顶部用与 new-api 数据看板一致的“成功率、平均延迟、吞吐量”摘要，按当前返回 models 执行同一简单平均规则；其下每个模型原样显示 success_rate、avg_latency_ms 与 avg_tps。吞吐量单位为 `t/s`。接口不返回站点级 request_count 或加权汇总；切换范围时保留上一份成功结果，错误只覆盖性能区块。站点列表中的 performance 来自服务端最近一次成功的 24 小时缓存，`unavailable` 时显示“暂未获取”，数值显示 `0`。

实例列表对 retired node 显示“已退役”和 retired_at，不再展示为当前 stale/offline，也不计入当前实例数；历史资源和已结束告警仍可下钻。节点重新出现后按新返回状态展示，不能复活旧告警文案。

区块分别处理 loading/error，不因单接口失败隐藏全页。点击卡片使用 TanStack Link 进入带好筛选参数的详细统计。

### 38.12 站点实例状态页

`/sites/:siteId/status` 展示该站点全部实例的当前 CPU、内存、磁盘、节点身份、有效状态、采样时间和 data_status；技术详情可展开查看 upstream_status 与运行时版本。页面一次读取实例当前值，不为每个实例重复请求；retired 实例显示退役状态和 retired_at，不计入当前实例数，但保留历史资源下钻。页面左上角固定提供“返回站点管理”，直接回到 `/sites`，与站点卡片的实例状态入口形成闭环，不经由站点详情页中转。

当前值接口在分钟切换期间必须保留紧邻上一分钟的最新成功快照，不能因为新分钟采集尚未完成而把在线实例、资源汇总和列表数据瞬间降为 0/未知/缺失；超过该一分钟缓冲窗口后仍按缺失展示，实例有效状态由服务端结合 last_seen_at 和实际 stale 阈值返回。

资源趋势支持 CPU、内存、磁盘指标，按 minute/hour/day 粒度和 avg/max/last 聚合切换，并支持可选 node_name；切换粒度时必须同时生成与后端契约对齐的默认闭合区间：minute 最近 60 分钟并对齐整分钟、hour 最近 24 小时并对齐北京时间整点、day 最近 30 天并对齐北京时间零点。资源接口不提供 month 粒度，“近一月”使用 day 粒度的最近 30 天范围。手工时间输入也必须按当前粒度对齐后再请求。图表之外提供可访问的数据表；孤立缺采样桶在曲线上连接相邻真实点以保持趋势可读，但不得补 0，可访问表仍逐桶显示缺失值。只有至少存在一个有限资源值时才创建图表，全空值显示明确空态。health_status 使用服务端有效阈值，`online/stale/offline/unknown` 和 `ok/warning/critical/unavailable` 均以状态徽标和文字表达。实例列表、汇总和趋势分别处理加载、错误与不完整状态，不能把 unavailable 或缺失数据渲染成真实零值。
分钟粒度只展示最近 60 个完整采样桶，且不得为每个点持续绘制大尺寸圆点造成视觉糊化；分钟图仅保留折线和悬停信息，小时/日图可显示点标记。

### 38.13 订阅计划目录页

交付全局 `/subscription-plans` 与强制站点 `/sites/:siteId/subscription-plans` 只读页面，主导航和站点详情均提供入口。页面明确说明“计划目录，不是订阅收入或用户订阅库存”；站点页只调用强制站点 API，不以前端过滤全局结果。页面参考模型审计拆分为“订阅计划 / 站点分析”Tabs：订阅计划视图展示用途说明、紧凑筛选和固定高度主列表，表格内部滚动，分页通过公共页脚固定在页面右下角；站点分析视图不显示列表筛选和分页，单独展示各站点的计划数量、启用、停用、缺失、完整性和采集时间。全局列表筛选支持站点、关键词、启用状态和 normal/missing 状态，站点页隐藏站点筛选。切换站点分析时清除列表筛选和分页，只把非默认 Tab、非默认列表筛选、非默认列表分页和导出任务 ID 写入 URL；首次打开必须保持 `/subscription-plans` 的短地址，不得序列化空字符串、空数组、第一页或默认每页数量。刷新、深链及前进后退恢复，修改筛选时页码归 1；列表页码超过末页时使用 replace 修正 URL 并重新请求末页内容。

列表展示计划标题/副标题、站点身份、远端 ID、币种和原始价格字符串、总额度、时长、额度重置周期、启用状态、远端状态、data_status、创建/更新时间和排序值。顶部概览展示 total/enabled/disabled/missing；站点分析展示逐站统计、data_status/as_of。用户可见名称统一使用“站点分析”或“站点计划情况”，不得使用含义不清的“站点计划拆分”。ID、金额、额度和计数保持字符串，不由前端换算、跨站汇总或推断收入；总额度、自定义有效期秒数和自定义重置秒数按 bigint 千分位展示并通过 `title` 保留接口原值，价格只做 Decimal 千分位与无意义尾零清理，不改变币种或金额含义。CSV/XLSX 只在订阅计划列表视图提供，冻结安全筛选并排除分页，沿用 ExportTaskSheet；页面无任何写操作。

## 39. VChart 和金额展示

### 39.1 图表组件

| 组件 | VChart 类型 | 用途 |
|---|---|---|
| MetricTrendChart | line/area | 请求、quota/金额、Token、活跃数趋势 |
| RankingBarChart | horizontal bar | Top N |
| DistributionChart | donut | 站点/模型/通道占比 |
| ResourceTrendChart | multi-line | CPU、内存、磁盘 |
| CompletenessChart | gauge/progress | 完整率；优先使用普通 Progress，只有 Dashboard 才用图 |

图表通过动态 import 分包，路由首屏先渲染 Skeleton。统一从 @/lib/vchart 取得 light/dark 主题，主题切换时更新 theme prop，不在组件内复制调色板。

### 39.2 数据点

前端不重新聚合服务端趋势。每个点直接映射：

~~~text
{
  bucketStart: number
  label: string
  value: number | null
  rawValue: string | null
  dataStatus: DataStatus
  isFinal: boolean
  siteBreakdown: SiteQuotaBreakdown[]
  reason?: AnyMessageRef
}
~~~

null 点必须形成断线；complete 零值正常连到 0；partial 点用虚线段或显式空心标记，并在 tooltip 标明“仅包含已完成站点”。如果 VChart 某个系列配置会自动把 null 转 0，数据适配层必须过滤该点并显式构造断段，不能依赖默认行为。

### 39.3 Tooltip

趋势 tooltip 固定显示：

- 时间桶和北京时间；
- 原始精确值；
- 数据状态；
- is_final/as_of；
- quota 指标下的每站 quota、quota_per_unit、USD 汇率、USD、CNY；
- partial 时的 complete_site_count/expected_site_count；
- missing/unavailable 的原因，不显示 0。

原因、能力检查、任务失败和告警主文案统一使用后端 `code + params` 映射 i18next；technical_detail/error_message 只在可展开的技术详情中显示，并同时提供 request_id。组件不得把自由文本当作状态分支条件。

Top N 和占比图点击后更新 URL 筛选或进入对应详情。

### 39.4 金额公式

前端 Decimal 计算：

~~~text
amount_usd = Decimal(quota).div(Decimal(quota_per_unit))
amount_cny = amount_usd.mul(Decimal(usd_exchange_rate))
~~~

优先使用站点最近一次有效汇率；站点从未成功返回汇率时才允许使用系统兜底值，并显示“兜底汇率”。两者都缺失或非正数时金额返回 null，界面显示金额 `0` 和“缺少汇率”状态，原始 quota 仍展示。跨站金额逐个 site_breakdown 计算后再 Decimal.sum，禁止先汇总 quota 再套任一站点汇率。

金额默认显示 2 位，tooltip 和导出显示 6 位；原始 quota 永远可查看。汇率旁显示“当前汇率”，避免被理解为历史汇率。

跨站合计中，只要任一 quota 非零的站点 rate_source=unavailable，整体 USD/CNY 返回 null，界面显示金额 `0` 和“部分站点缺少汇率”状态，不得只把已知站点相加后伪装成完整总额；site_breakdown 仍逐站展示可计算值。

## 40. 加载、空、错误和不完整状态

### 40.1 状态优先级

页面按以下顺序决定主体状态：

1. 首次加载：Skeleton；
2. 请求失败且无旧数据：ErrorState + Retry；
3. 请求成功且无业务对象：Empty；
4. 有旧数据且后台刷新：保留内容并显示轻量 fetching；
5. backfilling/partial：Alert + 可用部分数据；
6. missing/unavailable：对应点为空和 CompletenessAlert；
7. complete：正常。

不能用全屏 Spinner 覆盖已有数据；后台刷新不清空表格。

### 40.2 Empty 文案和动作

| 页面 | Empty | admin 动作 | viewer 动作 |
|---|---|---|---|
| 站点 | 尚未添加站点 | 新建站点 | 无 |
| 客户 | 尚未创建客户 | 新建客户 | 无 |
| 账户 | 当前筛选无纳管账户 | 添加账户/重置筛选 | 重置筛选 |
| 统计 | 范围内无流量 | 调整范围 | 调整范围 |
| 告警 | 当前没有匹配告警 | 重置筛选 | 重置筛选 |
| 导出 | 尚无导出任务 | 发起导出 | 发起导出 |

“无流量”只用于后端 data_status=complete 的零结果；missing 不能复用 Empty。

### 40.3 状态颜色之外的信息

所有状态同时使用文本、图标和语义 Badge。图表线型、点形和 tooltip 一起表达 partial/missing，满足色觉无障碍。

## 41. 响应式和无障碍

### 41.1 响应式

- 全局应用框架以 1024px 为桌面侧栏断点：小于 1024px 时主导航统一使用临时抽屉，Header 保留不小于 40px 的导航和账户触摸目标；大于等于 1024px 时显示可折叠的固定侧栏。768～1023px 的平板宽度不得同时占用固定侧栏和卡片内容区，页面内容不得因此缩窄或产生页面级水平溢出；
- 小于 640px：列表使用单列卡片；筛选仍以内嵌页面筛选区呈现，主筛选项自然换行，高级筛选项继续使用展开/收起；主操作固定在 Header 或底部 Drawer；
- 640～1024px：卡片 2 列，统计卡片 2 列；
- 大于等于 1024px：站点卡片 3 列，Dashboard 12 列网格；
- 大于等于 1440px：站点卡片可 4 列；
- 表格详情列在移动端转换为语义键值，不做横向挤压；
- 图表最小高度 280px，移动端 tooltip 使用点击锁定；
- Dialog 最大宽度适配内容，复杂长表单使用 Drawer 而不是超高 Dialog。
- TanStack Query/Router 调试工具仅在 development 模式装配，且显式默认收起；不得因浏览器保留的调试面板状态在刷新后遮挡业务界面或改变响应式验收结果，production 构建不得包含可见调试入口。

### 41.2 无障碍

- 所有图标按钮有 aria-label；
- 状态更新区域需要时使用 aria-live=polite，但 60 秒轮询不重复播报未变化内容；
- 表单 Label 与输入关联，错误通过 FieldError；
- AlertDialog 初始焦点落取消按钮；
- 数据表排序头暴露 aria-sort；
- 键盘可到达卡片操作、Tabs、筛选、分页和图表替代数据表；
- 图表必须提供“查看数据表”切换，不能作为唯一信息载体；
- SPA 路由切换后焦点必须落到 `#main-content`；从移动端临时主导航发起跳转时，应等待抽屉关闭及其焦点恢复流程结束后再聚焦主内容，不能让焦点回到已经关闭的导航触发按钮；
- 站点、客户和账户详情的共享完整性区必须说明其表示采集窗口完整性、独立于页面上方的今日摘要；当后端返回 `expected_unit_count=0` 时，不渲染缺失状态徽标、0% 或 0/0 覆盖率，统一显示“暂无可评估数据”。
- 站点、客户和账户详情的历史回填卡必须同时展示权威 `status`、进度和窗口计数。`failed` 即使因终态窗口计入进度而显示 100%，也必须保留醒目的“失败”状态和失败窗口数，禁止仅显示百分比造成“已成功完成”的误读；`pending/running/failed` 分别显示“等待中/进行中/失败”。
- 触摸目标不小于 40px；
- Skeleton 不进入可访问树或标记 aria-hidden。
- 页面级空态、首次加载错误态和数据表空/错误态的标题必须遵循当前页面的标题层级，不得由共享组件固定输出 `h3` 而在 `h1` 后跳过 `h2`。共享 EmptyTitle 默认使用 `h2`，确实嵌套在已有 `h2` 区块内时允许显式选择 `h3`；仅靠字号样式不得替代语义层级。

## 42. 导出前端闭环

点击导出：

1. 打开 ExportDialog；
2. 显示当前统计类型、时间范围、筛选和完整性；
3. 选择 Excel 或 CSV；

导出按钮不会直接把当前表格 DOM 转文件。ExportDialog 明确说明：

- 导出不受当前分页限制；

- 不完整区间会保留 data_status；
- 大范围导出在后台生成。
- 成功文件标明 data_snapshot_at 和 exported_at，全部数据行来自同一个数据库一致性快照；同一任务重试仍使用首次冻结的汇率快照。

### 44.1 国际化

使用单一简体中文扁平 JSON：

~~~text
web/src/i18n/locales/zh-CN.json
~~~

翻译键使用稳定语义 key，例如 `sites.title`、`data.backfilling`、`exports.create`；稳定 API/任务错误码和能力 message code 直接作为对应错误文案 key。组件通过 `useTranslation()` 调用 `t()`，常量配置只保存 key，不保存翻译结果。i18next 的唯一 `appLanguage` 常量固定为 `zh-CN`，`lng`、`fallbackLng` 和 `supportedLngs` 均由该常量派生；不得引入浏览器语言检测器、`changeLanguage` 调用或语言切换 UI。

`bun run i18n:check` 必须校验仅存在并加载 `zh-CN.json`、key 唯一、值 trim 后非空、稳定 API/任务错误码和能力 message code 全部存在，并扫描用户可见文案不得绕过 i18next 硬编码。检查命令只校验，不生成占位文案。新增稳定码必须在同一变更中补齐 `zh-CN` 文案。

后端使用稳定 code 驱动前端最终文案，中文 `message` 仅作为安全兜底。发布前以 `zh-CN` 执行登录、站点列表、统计、告警和导出五个页面的快照冒烟；断言不存在原始 code、`undefined`、空按钮、语言切换入口或布局溢出。机器检查保证 key 和非空，快照/人工记录保证核心路径语义可读。

### 44.2 性能

- Dashboard、用量统计、资源历史和普通业务详情不穿透远端站点，读取平台 MySQL；明确例外是添加账户时的单站远端用户搜索、admin 手动刷新，以及站点性能健康详情的单站实时代理。站点列表性能只读取服务端进程缓存，不同步等待上游；

### 44.3 前端验证命令

开发完成后必须通过：

~~~text
cd web
bun run check
~~~

`check` 必须依次覆盖 routes generate、tsgo typecheck、oxlint、oxfmt check、i18n:check 和 Rsbuild build；package.json 不得绕过其中任一项。

端到端验收使用独立命令 `bun run test:e2e`，运行 Playwright 的受控 Chromium 视口项目，输出 HTML、截图和无障碍冒烟报告。标准门禁中的业务 E2E 必须用路由 fixture 或专用隔离环境保持确定性，不得依赖开发库中某个可变站点、客户、账户、任务数量或管理员首次改密状态；需要核对当前开发库真实值的浏览器检查必须由显式环境开关单独运行，不能混入标准 `test:e2e`。对验收条目已经明确要求窄屏 cards、导航或无页面级水平溢出的关键页面，应在受控移动视口额外覆盖 375px，不把全部功能用例无差别重复执行。统计 fixture 中合法 bigint/decimal 字符串 `0` 是权威真实零，只有 `null`/缺失才显示 `-`；E2E 不得把完整或保留窗口中的真实零误断言为缺失。`bun run check` 是静态发布检查，不能被描述成已覆盖 E2E；根目录 `make acceptance` 会依次调用两者。

测试源码若显式校验 `testInfo.project.name`，允许集合必须与 `playwright.config.ts` 当前配置的 desktop、mobile、tablet-768、tablet-1024 项目保持一致；新增或移除视口时必须同步更新断言，不得让陈旧白名单把已配置的正式验收项目判为失败。

标准矩阵固定为四个 Playwright project：`chromium-desktop`、`chromium-mobile`、`chromium-tablet-768`、`chromium-tablet-1024`。移动项目使用 390×844，两个平板项目分别使用 768×1024 与 1024×768；关键 375px 窄屏条目继续由用例内显式视口覆盖，不另建第五个 project。

E2E 操作由异步查询填充或刷新的 Base UI Select 时，共享助手必须在每次重试中重新定位当前 `aria-expanded=true` 的 combobox，并按其运行时 `aria-controls` 精确绑定对应 listbox 与目标 option，成功选择后验证该 listbox 关闭；不得根据业务自定义 trigger ID 拼接 listbox ID，也不得用全页“最后一个可见 listbox”猜测归属。调用方不得为了检查弹层几何或选项存在性而重复选择当前值，应先执行真实值变化或只做只读断言。不得跨异步刷新长期持有可能被替换的 option DOM 节点，也不得用 Escape 影响父 Dialog、固定休眠、后台触发器点击或强制点击掩盖真实交互问题。

E2E 通过主导航切换路由时必须按当前响应式形态定位：桌面直接使用可见主导航链接，移动端先打开“主导航”Dialog，再在 Dialog 内定位链接；不得假定移动端链接仍位于桌面 `nav` DOM 子树中，也不得持有导航开合前创建的陈旧可见性判断。

## 系统设置与告警规则说明要求

- 系统设置页面必须为每个持久化设置显示独立的、面向运营人员的说明，说明其采集对象或受影响的业务行为、单位和适用范围；不得以同一通用说明替代探活、实时统计、资源采集、元数据、小时用量或历史回填的含义。
- 告警规则列表和规则编辑 Drawer 必须同时显示规则名称与其业务说明。说明必须明确监控对象、指标含义和单位；阈值、比较符与连续次数共同构成触发条件，不能要求用户理解原始 metric 键才能配置规则。
- 内建规则的 warning 与 critical 级别可共用同一业务说明，但界面必须保留各自的阈值、比较符和连续次数，便于用户判断实际触发条件。
- 告警规则页必须显示站点、采集、实例、账户、渠道五类业务分类，并提供分类、级别、启用状态和站点继承状态过滤；分类是快速定位入口，不能只展示原始 rule_key 或 metric。规则过滤项数量少，必须全部常显，不提供展开/收起；单值枚举过滤复用站点管理状态过滤的 FacetedFilter 组件并即时生效。Warning/Critical 同键规则的显示名称必须包含级别，不能渲染成两条同名规则。
- 告警事件和告警规则分别维护独立的 URL 分页、每页数量、过滤和排序状态。规则列表使用服务端分页；仅分类、规则、级别、指标、启用状态和更新时间提供排序入口，连续次数不排序；表头字段与 API sort_by 必须一一对应，切换过滤或排序时回到第 1 页。
# P0-B 使用日志共享契约

交付用户可见名称为“使用日志”的独立全局日志页 `/logs` 与站点日志页 `/sites/:siteId/logs`。该名称与 new-api `/api/log/` 的原生产品术语保持一致，涵盖充值、消费、管理、系统、错误、退款和登录等日志类型，不得把“使用”收窄解释为仅模型消费。站点详情页提供明确的“使用日志”入口；全局页调用 `GET /api/logs`，站点页调用 `GET /api/sites/:id/logs`，不得以全局接口加前端过滤模拟站点权限边界。

页面筛选状态必须写入 URL，并覆盖时间区间、type、username、model_name、token_name、channel_id、group、request_id、upstream_request_id；全局页另支持 `site_ids`。时间范围为左闭右开且最长 31 天，分页为 `p/page_size`。清除或修改任一筛选时页码归 1；刷新、浏览器前进后退和直接深链必须恢复相同查询。

列表只渲染后端 `LogItem` 的安全字段。桌面端使用可横向滚动表格，375px 使用 cards；关键消费字段与官方日志的信息结构保持一致并拆分为“模型 / 模式 / Tokens / 费用 / 时延”：模式显示流式或非流式，存在有效耗时和输出 Token 时以 bigint 运算派生整数 TPS；Tokens 第一行显示输入/输出，第二行在存在缓存数据时显示缓存读取与缓存写入，缓存写入优先使用 5m/1h 分项之和，否则使用总创建量；费用使用该日志所属站点的费率精确换算并同时显示人民币与美元，裸 quota 只作为详情中的审计值，缺少费率时金额显示 `0` 并明确提示；时延对流式请求显示首字延迟与总耗时，对非流式请求只显示总耗时，格式与官方一致使用紧凑英文单位（如 `320ms`、`5.0s`、`1m 5s`），未知首字延迟显示 `-`。每条记录还保留站点、时间、类型、用户、Token、Channel、Group、request ID、upstream request ID、后端已脱敏 content 和详情入口。列表 `total`、`id/site_id/remote_user_id/token_id/channel_id` 与所有计数保持十进制字符串，不经过 `Number`；分页以 BigInt 比较是否有下一页，不计算超出安全整数范围的最后页。IP 为空时显示“未记录”，不得推断或回填客户端地址。

详情使用只读 Dialog 展示同一 DTO 的完整安全字段，不重新请求不存在的详情接口。content 明确标注为后端脱敏摘要，并使用可换行的等宽文本；页面同时显示“日志只用于请求排障与运营审计，不构成财务事实，账务以 usage 统计为准”的固定提示。

页头展示 `data_status` 与 `as_of`。`partial/pending/unavailable/disabled` 均不得渲染成空结果；已有 items 时保留列表并展示完整性警告，没有 items 时展示与状态对应的原因说明和重试入口。全局列表中的站点列同时承担站点 breakdown，必须同时显示 `site_name` 和 bigint-safe `site_id`。

交付全局 `/pricing-groups` 与强制站点 `/sites/:siteId/pricing-groups` 只读页面，主导航和站点详情均提供入口。页面采用“单层总览指标、两个配置 Tabs、当前视图用途、主内容”层级；总览只出现一次，不再创建“站点概览”Tab。默认 Tab 固定为“分组配置”，第二个为“模型定价”。禁止供应商定价、只有数量没有对象名称的分组模型，以及按布尔值聚合的分组完整性孤立视图。

“分组配置”是分页目录，逐站直接展示组名、基础计费倍率、充值倍率、用户可选状态与说明、自动分组顺序、默认自动分组开关、用户组到计费组的覆盖倍率、特殊可见/隐藏规则和关联模型名；零模型分组明确显示“未关联模型”。“模型定价”逐站展示唯一模型记录、计费模式、固定价格或输入/输出/缓存/图像/音频价格维度、表达式文本、模型厂商元数据、可用分组、supported endpoints、normal/missing 与 as_of。全局站点筛选使用站点名称单选组件，库存状态使用单选组件；站点页面只调用强制站点 API，不得用全局结果前端过滤。

顶部指标固定为站点数、现存模型、现存分组、历史缺失模型，并在文案中说明 missing 是最近一次完整快照确认后的历史模型，而不是厂商标签变化。只有列表筛选、分页、非默认 Tab 和 export ID 写入 URL，首次打开保持 `/pricing-groups`；两个分页 Tab 的越界页都必须 replace 到各自末页并重新请求。CSV/XLSX 在两个 Tab 均提供并固定使用 `group_catalog|pricing_catalog`。

模型厂商字段固定命名为“模型厂商”，只表达 new-api 模型元数据归属；真正的上游供给来自渠道库存，页面提供渠道库存入口但不得声称 new-api 存在按厂商或渠道分别定价。decimal、ID 和计数均保持 branded string，禁止 JavaScript Number；页面不计算跨站价格总额、均价或货币换算。

所有视图在 partial/pending/unavailable 时保留已知事实。模型名称、覆盖组名与规则对象必须可直接阅读，数量只作为辅助汇总。billing expression 允许作为只读普通文本显示和导出，但不得执行、生成链接或解释 `header/param` 的运行时值；TypeScript、URL、DOM/aria/data、storage、console、trace、导出体与下载列必须不存在凭据、header 值、渠道密钥、原始响应或 mutation 参数。桌面表格、375px cards、键盘、触摸目标、无横向页面溢出和 axe WCAG 2A/2AA 均为 required 验收证据。

# D139 系统任务前端契约

交付用户可见名称为“系统任务”的全局 `/system-tasks` 与强制站点 `/sites/:siteId/system-tasks` 只读页面；名称与 new-api `/api/system-task/list` 的原生系统任务概念保持一致。主导航和站点详情均提供入口。页面只调用 pilot 的全局或对应站点 list/statistics API，绝不直接调用上游；URL 保存 `tab/page/pageSize/siteIds/types/statuses/createdStart/createdEnd/errorPresent/exportId`，站点页移除 `siteIds`。默认 URL 不生成时间边界，刷新、深链及前进后退必须保留长期 active 任务可见性。

TypeScript 使用 `log_cleanup|log_detail_cleanup|channel_test|model_update|midjourney_poll|async_task_poll` 和 `pending|running|succeeded|failed` 精确联合；`log_detail_cleanup` 只展示安全 `archived_days`。progress/result 必须按 D139 typed 判别联合呈现；计数/ID 保持 branded decimal string，不经 JavaScript Number。失败只展示 `error_present` 和稳定本地 `error_code` 的 i18n 文案，不显示、请求或推测原始错误。截断、ID gap、未知未来 type、current 失败、同步失败和 config fence 均显示 partial/unavailable、`data_error_code` 与 last successful as_of，已有任务不能被空态覆盖；`unavailable` 时不得使用普通“暂无数据”文案。

前端直接消费顶层 `truncated/truncation_reason/source_limit/observed_count`；`truncation_reason` 只接受 `null|source_limit|id_gap|source_limit_and_id_gap`，不得从行数或 `partial` 文案反推原因。

页面布局与模型审计保持一致：`fixedContent` 固定工作区，顶部紧凑 summary，其后为“任务列表 / 类型分析 / 状态分析 / 站点完整性”Tabs、当前视图一句话用途说明和仅列表视图显示的紧凑筛选栏；主表格或分析区占据剩余高度并内部滚动。只读边界与 terminal retention 合并为短提示，不得用大块告示抢占首屏。CSV/XLSX 仅在任务列表视图提供。桌面表格、375px cards、语义替代内容、键盘与触摸目标、无页面横向溢出和 axe WCAG 2A/2AA 均为 required。TypeScript、Query cache、URL、DOM/aria/data 属性、storage、console、trace 和导出预览都不得声明或携带 active_key、locked_by、payload/state/result raw JSON、error 原文、单任务详情地址或 mutation action。

分页底栏必须显示后端返回的精确 bigint 字符串总数，禁止用“当前页已观察行数 + 1”的控制值冒充总数。由于 bigint 总数不得转换为 JavaScript Number，系统任务列表使用顺序分页：上一页、当前页、下一页按 bigint 比较结果控制，隐藏需要把总页数转换为 Number 的“最后一页”动作。列表、统计或站点选项刷新失败但已有缓存数据时保留缓存并显示可重试的过期提示；首次加载失败才显示阻断式错误态。小于桌面表格断点时切换为可纵向滚动 cards，cards 必须展示任务身份、类型、状态、安全错误、进度、类型化结果、数据完整性以及远端创建/更新/采集时间，不得丢失桌面安全字段。
